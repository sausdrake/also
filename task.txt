Типы тестов для фронтенда
1. Юнит-тесты (компоненты)
Что тестируем	Инструмент	Что проверяем
React компоненты	Jest + React Testing Library	Рендер, события, состояния
Хуки (useAuth, useWebSocket)	Jest + @testing-library/react-hooks	Логика, edge cases
Утилиты (formatPrice, validateVin)	Jest	Форматирование, валидация
Zustand сторы	Jest	Состояние, действия
2. Интеграционные тесты (страницы + API)
Что тестируем	Инструмент	Что проверяем
Страница логина	Jest + MSW (Mock Service Worker)	Отправка формы, обработка ошибок
Страница аукциона	Jest + MSW	Загрузка данных, WebSocket, ставки
Личный кабинет	Jest + MSW	Депозит, ставки, заявки
3. E2E-тесты (сквозные сценарии)
Что тестируем	Инструмент	Что проверяем
Полный флог пользователя	Playwright / Cypress	Регистрация → заявка → ставка → победа
Кросс-браузерность	Playwright	Chrome, Firefox, Safari
Мобильная адаптация	Playwright (viewport)	375px, 768px, 1280px
WebSocket в реальном времени	Playwright	Обновление цены у всех клиентов
4. Тесты безопасности (фронтенд)
Уязвимость	Что проверяем	Инструмент
XSS через пользовательский ввод	Вставляем <script>alert(1)</script> в комментарий	Jest + React Testing Library
JWT в localStorage	Проверяем, что токен не виден в HTML	Playwright
CSRF	Проверяем, что запросы без токена отклоняются	Playwright
Rate limiting на клиенте	10+ ставок за минуту → блокировка	Playwright
📝 Примеры тестов для фронтенда
3.1. Юнит-тест (Jest + React Testing Library)
typescript
// AuctionCard.test.tsx
import { render, screen, fireEvent } from '@testing-library/react';
import { AuctionCard } from './AuctionCard';

test('XSS защита: название аукциона экранируется', () => {
  const maliciousProps = {
    id: 1,
    title: '<img src=x onerror=alert(1)>',
    price: 1000000,
    status: 'ACTIVE',
  };
  
  render(<AuctionCard {...maliciousProps} />);
  
  // Проверяем, что HTML не выполнился
  expect(screen.queryByText('<img')).toBeNull();
  expect(screen.getByText(/&lt;img/)).toBeInTheDocument();
});

test('Rate limiting: после 10 ставок кнопка блокируется', async () => {
  render(<BidForm auctionId={1} minBid={1000000} />);
  
  const button = screen.getByRole('button', { name: /сделать ставку/i });
  
  for (let i = 0; i < 11; i++) {
    fireEvent.click(button);
  }
  
  expect(button).toBeDisabled();
  expect(screen.getByText(/подождите/i)).toBeInTheDocument();
});
3.2. E2E-тест (Playwright)
typescript
// auction-flow.spec.ts
import { test, expect } from '@playwright/test';

test('Полный флоу: пользователь делает ставку и получает WebSocket обновление', async ({ page, context }) => {
  // Открываем два окна (продавец и покупатель)
  const buyerPage = await context.newPage();
  const observerPage = await context.newPage();
  
  // Логин
  await page.goto('/login');
  await page.fill('[name="username"]', 'buyer');
  await page.fill('[name="password"]', 'pass123');
  await page.click('button[type="submit"]');
  
  // Переход на аукцион
  await page.goto('/auction/1');
  
  // Проверка WebSocket подключения
  await expect(page.locator('.ws-status')).toHaveText('connected');
  
  // Ставка
  await page.fill('[data-testid="bid-amount"]', '1010000');
  await page.click('[data-testid="place-bid"]');
  
  // Ждём успешное сообщение
  await expect(page.locator('.toast-success')).toBeVisible();
  
  // Проверяем, что второй клиент получил обновление через WebSocket
  await observerPage.goto('/auction/1');
  await expect(observerPage.locator('[data-testid="current-price"]')).toHaveText('1,010,000');
});

test('XSS через VIN на странице аукциона', async ({ page }) => {
  // Создаём заявку с XSS в VIN
  await page.goto('/profile/requests');
  await page.click('[data-testid="create-request"]');
  await page.fill('[name="vin"]', '<script>alert("XSS")</script>');
  await page.fill('[name="brand"]', 'BMW');
  await page.fill('[name="model"]', 'X5');
  await page.fill('[name="year"]', '2022');
  await page.click('[data-testid="submit-request"]');
  
  // Заходим на страницу аукциона (после одобрения админом)
  await page.goto('/auction/1');
  
  // Проверяем, что alert не выполнился
  let alertTriggered = false;
  page.on('dialog', () => alertTriggered = true);
  expect(alertTriggered).toBe(false);
});

test('Неавторизованный пользователь не может сделать ставку', async ({ page }) => {
  await page.goto('/auction/1');
  
  const bidButton = page.locator('[data-testid="place-bid"]');
  await expect(bidButton).toBeDisabled();
  await bidButton.click();
  
  await expect(page).toHaveURL('/login');
});

Напиши фронтенд-тесты (Jest + React Testing Library + Playwright) для React/TypeScript приложения по следующим сценариям:

## XSS и безопасность

1. Пользователь вводит <script>alert('xss')</script> в:
   - VIN при создании заявки
   - Комментарий при ставке
   - Название автомобиля
   → Проверить, что скрипт не выполнился, HTML экранирован

2. JWT токен в localStorage: проверить, что токен не виден в исходном HTML (не попал в SSR)

## Rate limiting

3. Пользователь делает 11 ставок за 1 минуту → 11-я блокируется, появляется сообщение "Слишком много ставок"

4. Пользователь делает 5 неудачных попыток входа → кнопка блокируется на 15 минут

## Доступ и авторизация

5. Неавторизованный пользователь:
   - Не видит кнопку "Торговать"
   - Не видит кнопку "Напомнить"
   - При попытке ставки → редирект на /login

6. Пользователь с ролью USER не видит админ-панель и панель диагноста

7. Пользователь пытается перейти по прямому URL /admin → редирект на /forbidden

## WebSocket и real-time

8. При ставке в одном окне → цена обновляется во всех открытых окнах (Playwright, 3 окна)

9. При обрыве соединения WebSocket → автоматическое переподключение (проверить через мок)

10. Таймер на странице аукциона:
    - Правильно отображает время до старта/окончания
    - При переходе времени меняется статус (без перезагрузки страницы)

## Валидация форм

11. Создание заявки:
    - VIN не 17 символов → ошибка
    - Год > текущего → ошибка
    - Марка пустая → ошибка

12. Ставка:
    - Сумма < минимальной → кнопка неактивна
    - Поле ввода не может быть пустым

13. Пополнение депозита:
    - Сумма < 100 → ошибка
    - Отрицательная сумма → ошибка

## Адаптивность и мобильные устройства

14. На мобильном устройстве (viewport 375px):
    - Меню сворачивается в бургер
    - Карточки в 1 колонку
    - Фильтры в выпадающий список

15. На планшете (viewport 768px) карточки в 2 колонки

16. На десктопе (viewport 1280px) карточки в 3-4 колонки

## Производительность

17. Список из 100 аукционов рендерится быстрее 2 секунд

18. Ленивая загрузка фото (IntersectionObserver): фото подгружаются при скролле

19. Infinite scroll вместо пагинации работает без утечек памяти

## Сквозные (E2E) сценарии

20. Регистрация → создание заявки → диагност берёт → заполняет отчёт → админ одобряет → создаёт аукцион → ставка → победа (полный флоу)

21. Регистрация → пополнение депозита → ставка → победа → проверка истории транзакций

22. Регистрация → Buy Now (на CREATED аукционе) → аукцион завершён

23. Админ создаёт шаблон анкеты → диагност его видит и использует

24. Пользователь включает уведомления → браузер запрашивает разрешение → разрешает → уведомление приходит

## Интеграция с бэкендом

25. При ошибке 401 → редирект на /login, токен удалён

26. При ошибке 403 → показ сообщения "Недостаточно прав"

27. При потере соединения с бэкендом → показ сообщения "Сервер недоступен"

## Конфиденциальность и логирование

28. Пароль не отображается в консоли (console.log не выводит пароль)

29. Токен не попадает в URL (только в заголовки)

30. Сообщения об ошибках не раскрывают внутреннюю структуру системы (нет stack trace)

## Мультиязычность (RU/KY)

31. Переключение языка меняет все тексты на странице

32. После перезагрузки страницы язык сохраняется (localStorage)

33. Даты отображаются в формате выбранного языка

## Доступность (a11y)

34. Навигация с клавиатуры (Tab, Enter) работает

35. Есть атрибуты aria-label для кнопок без текста

36. Цветовой контраст соответствует стандарту WCAG 2.1 (AA)

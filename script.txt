СЦЕНАРИИ РАБОТЫ СИСТЕМЫ
СЦЕНАРИЙ 1. ПОКУПАТЕЛЬ ХОЧЕТ ВЫСТАВИТЬ СВОЮ МАШИНУ НА АУКЦИОН
Актёр: Пользователь с ролью USER

Шаг	Действие	Система
1	Пользователь заходит в личный кабинет → «Мои заявки» → нажимает «Подать заявку»  Открывается форма создания заявки
2	Пользователь заполняет поля: марка, модель, год, VIN.	Валидирует VIN (17 символов), проверяет уникальность. Сохраняет как черновик
3	Пользователь нажимает «Отправить заявку»	Система проверяет наличие депозита (сумма для блокировки). Если достаточно — статус заявки становится PENDING. Если нет — ошибка «Пополните депозит»
4	Пользователь видит заявку в списке со статусом «На рассмотрении»	Кнопки: «Отозвать», «Просмотр»
СЦЕНАРИЙ 2. ДИАГНОСТИК ПРИНИМАЕТ ЗАЯВКУ В РАБОТУ
Актёр: Диагностик с ролью DIAGNOSTIC

Шаг	Действие	Система
1	Диагностик заходит в панель диагноста → «Доступные заявки»	Показывает список заявок со статусом PENDING
2	Диагностик нажимает на карточку заявки	Открываются детали: марка, модель, год, VIN, фото от пользователя
3	Диагностик нажимает «Взять в работу»	Заявка переходит в статус IN_PROGRESS. Автоматически создаётся черновик отчёта. Открывается страница выбора шаблона
4	Диагностик выбирает шаблон (Седан, Внедорожник, Мотоцикл и т.д.)	Открывается страница заполнения отчёта с группами и пунктами из выбранного шаблона
СЦЕНАРИЙ 3. ДИАГНОСТИК ЗАПОЛНЯЕТ ОТЧЁТ
Актёр: Диагностик с ролью DIAGNOSTIC

Шаг	Действие	Система
1	Диагностик видит страницу заполнения. Слева — группы (Кузов, Салон, Двигатель, Ходовая часть, Электрика, Документы)	Группы раскрываются по клику
2	Диагностик открывает группу «Кузов». Видит пункты: «Состояние ЛКП», «Царапины», «Вмятины», «Коррозия»	Для каждого пункта — звёзды оценки (1-5), поле комментария, кнопки загрузки фото/видео
3	Диагностик ставит оценку 4 звезды, пишет комментарий «Небольшая царапина на заднем бампере», загружает 2 фото	Система сохраняет ответ. Прогресс заполнения группы обновляется
4	Диагностик не знает, как оценить пункт «Работа двигателя» — нажимает «Пропустить»	Пункт помечается как пропущенный (только если пункт не обязательный)
5	Диагностик заполнил 80% пунктов, но хочет закончить позже → нажимает «Сохранить черновик»	Отчёт сохраняется со статусом DRAFT. Заявка остаётся IN_PROGRESS
6	Через день диагност заходит в «Мои отчёты» → находит черновик → нажимает «Продолжить»	Открывается страница с уже заполненными данными
7	Диагностик заполнил все обязательные пункты → нажимает «Отправить на проверку»	Система валидирует: все обязательные пункты заполнены, обязательные фото загружены. Статус отчёта становится COMPLETED. Заявка переходит в статус COMPLETED. Админ получает уведомление
СЦЕНАРИЙ 4. АДМИН ПРОВЕРЯЕТ И ОДОБРЯЕТ ОТЧЁТ
Актёр: Администратор с ролью ADMIN

Шаг	Действие	Система
1	Админ заходит в админ панель → «Отчёты диагностов»	Видит список отчётов со статусом COMPLETED
2	Админ нажимает на отчёт	Открывается детальная страница: информация об автомобиле, заявителе, диагносте. Все группы и пункты с оценками, комментариями, фото/видео
3	Админ видит, что всё заполнено правильно → нажимает «Одобрить»	Отчёт получает статус APPROVED. Автоматически создаётся запись в таблице Vehicle (автомобиль готов к аукциону). Заявка получает статус APPROVED. Диагност и заявитель получают уведомления
4	Если админ видит ошибки → нажимает «Отклонить»	Открывается модалка с полем «Причина отклонения». Админ пишет: «Не хватает фото двигателя». Отчёт получает статус REJECTED. Диагност получает уведомление с причиной
СЦЕНАРИЙ 5. АДМИН СОЗДАЁТ АУКЦИОН
Актёр: Администратор с ролью ADMIN

Шаг	Действие	Система
1	Админ заходит в админ панель → «Аукционы» → нажимает «Создать аукцион»	Открывается форма создания
2	Админ выбирает автомобиль из списка APPROVED (без активных аукционов)	Подтягиваются данные автомобиля (марка, модель, год, VIN)
3	Админ загружает главное фото (обязательно) и дополнительные фото/видео	Система сохраняет медиа
4	Админ заполняет: стартовая цена, резервная цена (опционально), Buy Now цена (опционально), шаг ставки, время начала, время окончания	Валидация: стартовая > 0, резервная >= стартовой, Buy Now > стартовой, шаг > 0, время окончания > времени начала
5	Админ нажимает «Создать»	Аукцион создаётся со статусом CREATED. Автомобиль получает статус IN_AUCTION
СЦЕНАРИЙ 6. АДМИН ПОДТВЕРЖДАЕТ СТАРТ АУКЦИОНА
Актёр: Администратор с ролью ADMIN

Шаг	Действие	Система
1	Админ видит в списке аукционов, что через 2 часа начинается аукцион. На карточке аукциона появляется кнопка «Подтвердить запуск»	Система показывает уведомление: «Требуется подтверждение старта для аукциона BMW X5»
2	Админ нажимает «Подтвердить запуск»	Аукцион получает отметку «подтверждён». В установленное время система автоматически меняет статус на ACTIVE
3	Если админ не подтвердил за 2 часа до старта	Система автоматически отменяет аукцион (статус CANCELLED). Автомобиль возвращается в статус APPROVED
СЦЕНАРИЙ 7. ПОКУПАТЕЛЬ УЧАСТВУЕТ В ТОРГАХ
Актёр: Пользователь с ролью USER

Шаг	Действие	Система
1	Покупатель заходит на главную страницу, видит активные аукционы	Карточки с фото, ценой, таймером, кнопкой «Торговать»
2	Покупатель нажимает «Торговать»	Переход на страницу аукциона
3	Покупатель видит текущую цену 2 500 000 сом, минимальный шаг 10 000 ₸, поле ввода предзаполнено 2 510 000 ₸	WebSocket подключается к каналу /topic/auction/1
4	Покупатель нажимает «Сделать ставку»	Система проверяет: аукцион активен, сумма >= минимальной, у пользователя достаточно депозита (1% от стартовой — 10 000 ₸ блокируются). Ставка сохраняется
5	Цена обновляется до 2 510 000 сом	WebSocket рассылает обновление всем клиентам. У всех открытых страниц аукциона цена меняется мгновенно
6	Если покупателя обогнали	Приходит уведомление: «Вас обогнали в ставке. Новая цена: 2 520 000 ₸»
СЦЕНАРИЙ 8. ПОКУПАТЕЛЬ ПОБЕЖДАЕТ В АУКЦИОНЕ
Актёр: Пользователь с ролью USER

Шаг	Действие	Система
1	Аукцион завершается по времени. Последняя ставка — 2 520 000 сом, резервная цена (1 500 000 сом) достигнута	Система определяет победителя (покупатель), статус аукциона становится COMPLETED
2	Победитель получает уведомление: «Поздравляем! Вы выиграли аукцион BMW X5»	В личном кабинете, в разделе «Мои ставки» → «Победы» появляется запись. Депозит победителя остаётся заблокированным
3	Проигравшие участники получают уведомление: «Вы проиграли аукцион BMW X5»	Их заблокированные депозиты размораживаются автоматически
4	Покупатель заходит в «Мои ставки» → «Победы» → нажимает «Перейти к оплате»	Открывается инструкция по оплате. После подтверждения оплаты админ размораживает депозит победителя
СЦЕНАРИЙ 9. ПОКУПАТЕЛЬ ПОЛЬЗУЕТСЯ BUY NOW
Актёр: Пользователь с ролью USER

Шаг	Действие	Система
1	Покупатель видит аукцион, который ещё не начался (статус CREATED). На карточке есть цена Buy Now — 3 200 000 сом который активен только до старта аукциона	Кнопка «Купить сейчас» активна
2	Покупатель нажимает «Купить сейчас»	Система проверяет: Buy Now цена установлена, пользователь не является владельцем автомобиля, на депозите достаточно средств (1% от стартовой). Блокирует депозит
3	Аукцион немедленно завершается со статусом COMPLETED. Покупатель становится победителем	Все участники получают уведомление об окончании аукциона через Buy Now
СЦЕНАРИЙ 10. НЕАВТОРИЗОВАННЫЙ ПОЛЬЗОВАТЕЛЬ ПРОСМАТРИВАЕТ АУКЦИОНЫ
Актёр: Неавторизованный пользователь (GUEST)

Шаг	Действие	Система
1	Пользователь заходит на сайт	Видит главную страницу с карточками аукционов. Кнопки «Торговать» и «Напомнить» отсутствуют
2	Пользователь нажимает на карточку аукциона	Переход на страницу аукциона. Цена, таймер, история ставок — всё видно. Но форма ставки заблокирована
3	Пользователь нажимает «Отчёт диагноста»	Открывается модалка с полным отчётом (300+ пунктов). Можно просматривать, но нельзя редактировать
4	Пользователь пытается нажать «Сделать ставку»	Появляется модалка: «Войдите или зарегистрируйтесь, чтобы участвовать в торгах»
СЦЕНАРИЙ 11. ПОЛЬЗОВАТЕЛЬ ПОПОЛНЯЕТ ДЕПОЗИТ
Актёр: Пользователь с ролью USER

Шаг	Действие	Система
1	Пользователь заходит в личный кабинет → «Депозит»	Видит баланс (доступный, заблокированный, общий)
2	Нажимает «Пополнить»	Открывается модалка с полем ввода суммы и предустановленными кнопками (500, 1000, 5000, 10000 сом)
3	Вводит 5000 сом, нажимает «Пополнить»	В демо-режиме баланс увеличивается. В боевом — перенаправление на платёжный шлюз. В истории транзакций появляется запись «Пополнение на 5000 сом»
СЦЕНАРИЙ 12. АДМИН НАСТРАИВАЕТ СИСТЕМУ
Актёр: Администратор с ролью ADMIN

Шаг	Действие	Система
1	Админ заходит в админ панель → «Настройки системы»	Видит поля: «Депозит (%)», «Комиссия платформы (%)», «Время подтверждения старта (часы)», «Время скрытия завершённых аукционов (часы)»
2	Админ меняет «Депозит» с 1% на 2% и нажимает «Сохранить»	Система обновляет значение. При следующих ставках будет блокироваться 2% от стартовой цены
3	Админ меняет «Время скрытия завершённых аукционов» с 24 на 48 часов	Завершённые аукционы будут видны пользователям 48 часов, потом исчезнут из ленты
СЦЕНАРИЙ 13. АДМИН СОЗДАЁТ ШАБЛОН АНКЕТЫ
Актёр: Администратор с ролью ADMIN

Шаг	Действие	Система
1	Админ заходит в админ панель → «Шаблоны анкет» → нажимает «Создать шаблон»	Открывается конструктор шаблонов
2	Админ вводит название «Седан», выбирает тип кузова «SEDAN»	Система сохраняет базовую информацию о шаблоне
3	Админ нажимает «Добавить группу»	Открывается модалка: поле «Название группы». Админ вводит «Кузов» → нажимает «Сохранить»
4	Админ добавляет вторую группу «Салон», третью «Двигатель», четвёртую «Ходовая часть», пятую «Документы»	Группы отображаются в списке. Порядок можно менять перетаскиванием (drag&drop)
5	Админ открывает группу «Кузов» → нажимает «Добавить пункт»	Открывается модалка редактирования пункта
6	Админ заполняет: название «Состояние ЛКП», описание «Оценка состояния лакокрасочного покрытия», включает чекбоксы «Требовать оценку», «Требовать фото», «Обязательный пункт»	Система сохраняет пункт. Он появляется в группе «Кузов»
7	Админ добавляет ещё пункты: «Царапины», «Вмятины», «Коррозия»	Каждый пункт может иметь свои настройки (оценка, фото, видео, обязательный)
8	Админ переходит в группу «Двигатель», добавляет пункт «Работа двигателя» (оценка + видео, без фото)	Система сохраняет настройки
9	Админ нажимает «Активировать шаблон»	Шаблон становится доступен для диагностов
Drag&Drop порядок:

Админ может перетаскивать группы мышкой для изменения порядка

Внутри группы можно перетаскивать пункты

Порядок сохраняется в БД (поле sort_order)

СЦЕНАРИЙ 14. АДМИН РЕДАКТИРУЕТ ШАБЛОН
Актёр: Администратор с ролью ADMIN

Шаг	Действие	Система
1	Админ видит в списке шаблонов «Седан» → нажимает «Редактировать»	Открывается конструктор с уже созданными группами и пунктами
2	Админ замечает, что пункт «Работа двигателя» должен быть обязательным → нажимает на ✏️ рядом с пунктом	Открывается модалка редактирования, админ включает чекбокс «Обязательный пункт» → нажимает «Сохранить»
3	Админ хочет удалить группу «Ходовая часть» → нажимает 🗑️	Система запрашивает подтверждение: «Удалить группу и все пункты внутри?» После подтверждения группа удаляется
4	Админ хочет скопировать шаблон «Седан» для создания шаблона «Внедорожник» → нажимает «Копировать»	Открывается модалка «Новое название шаблона». Админ вводит «Внедорожник» → сохраняет. Создаётся точная копия, статус «Неактивен»
5	Админ открывает скопированный шаблон, добавляет пункты «Состояние лебёдки», «Состояние внедорожных шин», «Защита картера»	Система сохраняет новые пункты
6	Админ активирует шаблон «Внедорожник»	Оба шаблона активны. Диагносты видят оба при выборе
СЦЕНАРИЙ 15. ДИАГНОСТИК ВЫБИРАЕТ ШАБЛОН И ЗАПОЛНЯЕТ ОТЧЁТ
Актёр: Диагностик с ролью DIAGNOSTIC

Шаг	Действие	Система
1	Диагностик взял заявку в работу. Система предлагает выбрать шаблон	Показываются карточки активных шаблонов: «Седан», «Внедорожник», «Мотоцикл». У каждого указано количество пунктов
2	Диагностик выбирает «Седан»	Открывается страница заполнения отчёта. Группы и пункты загружаются из шаблона
3	Диагностик начинает заполнять пункты. Для пункта «Состояние ЛКП» ставит оценку 4 звезды, пишет комментарий «Небольшая царапина на заднем бампере», нажимает «Добавить фото»	Открывается окно выбора файлов. Диагностик выбирает 2 фото с компьютера. Фото загружаются в облако (S3 / Cloudinary), ссылки сохраняются в БД
4	Для пункта «Работа двигателя» диагност записывает видео на телефон, загружает его через форму	Видео загружается в облако, ссылка сохраняется в БД
5	Диагностик не может оценить пункт «Состояние шин» (машина на подъёмнике) → нажимает «Пропустить»	Пункт помечается как пропущенный. Если пункт обязательный — кнопка «Пропустить» неактивна или отсутствует
6	Диагностик заполнил 80% пунктов, но хочет продолжить завтра → нажимает «Сохранить черновик»	Все ответы (оценки, комментарии, ссылки на фото/видео) сохраняются. Статус отчёта — DRAFT
7	На следующий день диагност заходит в «Мои отчёты» → нажимает «Продолжить»	Загружаются ранее сохранённые ответы. Диагност видит уже загруженные фото и видео
8	Диагност заполняет оставшиеся пункты, нажимает «Отправить на проверку»	Система проверяет: все обязательные пункты заполнены, обязательные фото загружены. Отчёт сохраняется со статусом COMPLETED. Все ссылки на медиа уже в БД

Шаг	Действие	Система

2	Бэкенд генерирует presigned URL (срок действия — 5 минут)	URL содержит путь к файлу в облаке
3	Фронтенд загружает файл напрямую в облачное хранилище по полученному URL	Файл сохраняется в S3 / Cloudinary
4	Фронтенд получает публичную ссылку на загруженный файл	Ссылка вида https://cdn.auction.kg/photos/auction123/photo1.jpg
5	Диагностик нажимает «Сохранить отчёт»	Фронтенд отправляет на бэкенд ответы вместе с массивом photo_urls
6	Бэкенд сохраняет массив photo_urls в БД (поле photo_urls типа TEXT[] или JSONB)	В базе данных хранятся только ссылки, сами файлы — в облаке
Преимущества такого подхода:

База данных не перегружается большими файлами

Быстрая загрузка фото/видео на страницах (через CDN)

Лёгкое масштабирование (облачное хранилище)

СЦЕНАРИЙ 17. АДМИН СОЗДАЁТ АУКЦИОН С ФОТО И ВИДЕО
Актёр: Администратор с ролью ADMIN

Шаг	Действие	Система
1	Админ создаёт аукцион, заполняет все цены и время	Система сохраняет аукцион со статусом CREATED
2	Админ загружает главное фото (обязательно) и дополнительные фото/видео	Файлы загружаются в облако (по той же схеме с presigned URL). Ссылки сохраняются в таблице auctions (поля main_photo_url, additional_photo_urls, video_url)
3	Админ нажимает «Создать»	Аукцион сохраняется. На странице аукциона и на карточке будет отображаться главное фото
СЦЕНАРИЙ 18. ПОКУПАТЕЛЬ ПРОСМАТРИВАЕТ ОТЧЁТ ДИАГНОСТА
Актёр: Пользователь с ролью USER (или GUEST)

Шаг	Действие	Система
1	На странице аукциона пользователь нажимает «Отчёт диагноста»	Открывается модалка с отчётом
2	Пользователь видит сводку: общая оценка 4.8, ключевые недостатки (пункты с оценкой ≤ 3)	Система группирует и подсвечивает проблемные места
3	Пользователь нажимает «Полный отчёт»	Открывается полная версия отчёта со всеми 300+ пунктами, сгруппированными по разделам
4	Пользователь нажимает на миниатюру фото	Фото открывается в полноразмерном режиме (лайтбокс)
5	Пользователь нажимает на видео	Видео открывается в плеере (если ссылка на YouTube/Vimeo) или скачивается
